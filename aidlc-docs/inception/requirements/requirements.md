# moviedl 要件定義

## 概要

多数の動画配信サイトから動画をダウンロードできる GUI アプリケーション。

---

## 機能要件

### ダウンロード

- 動画サイトの URL を入力して動画をダウンロードできる
- 対応サイトは 1000 以上
- 最高画質でダウンロードできる
- 保存先ディレクトリをユーザーが選択できる（デフォルトは `~/Downloads`）

### ダウンロード状態とリスト管理

アイテムは以下の3つのリストのいずれかに属する：

| リスト | 説明 |
|---|---|
| **ダウンロード待ちキュー** | 登録済みで未開始のアイテム |
| **ダウンロード実行中リスト** | 現在ダウンロードが進行中のアイテム |
| **一時停止中リスト** | 一時停止されたアイテム |

### キュー

- 複数の URL を連続して登録できる
- **既にリストに同一 URL のアイテムが存在する場合、その URL は登録しない（重複登録の防止）。** 比較は完全一致。単一動画・プレイリスト選択のいずれの経路でも適用する。実行中・待機中・一時停止中・エラーのいずれの状態のアイテムも重複判定の対象とする（完了・キャンセルはリストから消えているため対象外）
- URL の登録と実際のダウンロード処理は独立している
- **URL 登録時の動画情報取得（yt-dlp による問い合わせ）は非同期に行い、取得完了を待たずに次の URL を入力・登録できる**
- 取得中の URL は UI 上に「取得中」アイテムとして可視化する
- **アプリウィンドウ内のどこにブラウザタブやテキストから URL をドラッグ&ドロップしても、「追加」ボタンを押さずに即座に登録処理を開始する**（ドロップ可能範囲は入力欄に限定せずウィンドウ全体）
- ドロップ時にアプリ外のページ遷移・別ウィンドウ表示を起こさない
- ドロップされたデータに複数の URL が含まれる場合（改行区切り）、それぞれを個別に登録する
- **同時ダウンロード数（自動補充の上限）をユーザーが 0〜10 の範囲でプルダウンメニューから選択できる**（デフォルトは 0）
- **実行中リストのアイテム数が設定値を下回ると、待ちキューにアイテムがある限り先頭から順に実行中リストへ移動し、設定値まで補充する**
- 実行中リストのアイテム数が設定値に達している場合は自動補充は行われない
- 設定値を引き上げたときは、待ちキューに余裕分のアイテムがあれば即座に補充される
- 設定値を引き下げたとき、既に実行中のアイテムは停止させない（実行中のダウンロードはそのまま完了まで継続する）
- 手動開始（後述）による並行ダウンロードは上限の対象外（設定値を超えて開始できる）

#### 同時ダウンロード数 0（登録のみモード）

- **0 を選択した場合、自動補充は一切行わない。** URL の登録（待ちキューへの追加）だけが行われ、ダウンロードは開始されない
- URL 登録に付随する処理（動画情報の取得、プレイリストの一覧取得・ファイル選択、重複チェック）は 0 でも従来どおり動作する。抑止されるのは実際のダウンロード開始のみ
- 0 に切り替えた時点で実行中のアイテムがあれば、それらは停止せずそのまま継続する（上記の引き下げ時ルールと同じ）
- 0 のときも**手動開始・再開は許可する**（手動開始は上限の対象外というルールを維持）。0 は「自動では始めない」の意味であり、ユーザーが明示的に開始したものは動く
- 0 から 1 以上に引き上げた時点で、待ちキューのアイテムが先頭から設定値まで自動補充される
- **アプリ起動時の初期値は 0**（設定は永続化せず、起動するたびに 0 に戻る）。起動直後は登録した URL が自動でダウンロードされることはなく、ユーザーが同時ダウンロード数を設定するか手動開始した時点で初めてダウンロードが始まる
- プルダウンの 0 は意味が伝わるよう `0（登録のみ）` と表示する

### 一時停止・再開

- 実行中リストのアイテムを個別に一時停止できる（実行中 → 一時停止中へ移動）
- 一時停止によって実行中リストが空になった場合は、自動補充ルールにより待ちキューから次のアイテムが開始される
- 一時停止中リストのアイテムはユーザーが手動で再開できる（一時停止中 → 実行中へ移動）

### 手動開始

- 待ちキューおよび一時停止中リストのアイテムは、ユーザーが手動で実行中リストへ移動できる
- これにより実行中リストに複数アイテムを並行ダウンロードさせることができる（同時ダウンロード数の上限なし）
- 同時ダウンロード数が 0 のときも手動開始は可能（上記「同時ダウンロード数 0（登録のみモード）」を参照）

### ファイル選択

- プレイリストや複数動画を含む URL を登録した場合、含まれる動画の一覧を表示する
- ユーザーはその一覧から個別にダウンロードするファイルを選択できる
- 選択されたファイルはそれぞれ独立したキューアイテムとして待ちキューに追加される

### キャンセル

- 3 つのリストのいずれに属するアイテムもいつでもキャンセル・削除できる

### エラー時の挙動

- ダウンロードがエラー終了したアイテムは **リストから自動削除してはならない**
- エラー状態のアイテムはエラーであることが視覚的にわかる形でリストに残し続け、エラー理由を表示する
- ユーザーは以下の操作ができる:
  - **リトライ**: 同じ URL でダウンロードを再試行する（待ちキューに戻り、自動補充で実行される）
  - **削除**: エラーアイテムをリストから明示的に取り除く
  - **URL コピー**: そのアイテムの元 URL をクリップボードにコピーする（リトライしても直らない場合に、通常のブラウザ等で代替ダウンロードするため）
- 理由: エラー原因はディスクフル・一時的なネットワーク障害など、ユーザーの対処でリトライ可能なケースが多い。自動消去するとユーザーは原因を確認できず、復旧手段も失う
- 後処理（ffmpeg 結合）の失敗のように**リトライでは直らない**場合もあるため、URL コピーで他手段に逃がせるようにする

### URL のコピー

- ダウンロードリストの各アイテムから、登録時の元 URL をワンクリックでクリップボードにコピーできる（エラー時に限らず、全状態で可能）

### 自動削除（成功・キャンセル時のみ）

- ダウンロードが正常完了したアイテムはリストから自動削除する
- ユーザーがキャンセルしたアイテムはリストから自動削除する
- **エラー終了したアイテムは自動削除の対象外**（上記「エラー時の挙動」を参照）

### 進捗表示

ダウンロード中は以下を表示する：

- 進捗率（%）
- ファイルサイズ
- ダウンロード速度
- 残り時間（ETA）
- 経過時間

### バージョン表示

- アプリ画面上でビルドのバージョンを確認できる（リリースビルドは `v0.1.8` などのタグ、それ以外は `dev` とビルド日を表示）

### 依存ツール管理

- 必要なツールが未インストールの場合、アプリ内から案内またはインストールできる
- yt-dlp は全プラットフォームでアプリ内からダウンロード・配置する
- ffmpeg は Windows ではアプリ内からダウンロード・配置する（バイナリには同梱しない）。macOS は Homebrew のインストールを案内する

#### yt-dlp の更新

**背景:** 本アプリの取得能力は実質すべて yt-dlp に依存しており、動画サイト側の仕様変更への追随は yt-dlp の更新でしか行えない。したがってアプリ本体の更新より **yt-dlp を新しく保てることのほうが重要**である。

- **インストール済みであっても、ユーザーは任意のタイミングで yt-dlp を最新版へ更新できる**
- 更新は**ユーザーが明示的に指示したときのみ**行う。起動時・定期の自動更新チェックは行わない
- 更新の操作は yt-dlp がインストール済みかどうかに関わらず常時可能（未インストール時のバナーとは独立した導線）
- インストール済み yt-dlp のバージョンを画面上で確認できる（更新されたかをユーザーが判断できるようにするため）
- 更新時に生存している yt-dlp プロセス（ダウンロード実行中・一時停止中・情報取得中）は、**すべて停止してから**実行ファイルを置き換える
- 停止によって影響を受けるアイテムが**ある場合のみ**、件数を示した確認を求める。影響がなければ確認なしで更新する
- 停止されたダウンロードは待ちキューへ戻す。**進捗は保持されず 0% からやり直しになる**ことを確認時に明示する
- **更新が失敗しても既存の yt-dlp を壊してはならない。** 失敗時は従来のバージョンでそのまま動作を継続できること
- **ネットワーク失敗でユーザーの進捗を失わせてはならない。** 新版のダウンロードと検証が成功した後に初めて停止・置き換えを行う

## m3u8（HLS）対応

**意図分析:**

| 項目 | 判定 |
|---|---|
| ユーザー要求 | 「m3u8 という拡張子のファイルで示される動画をダウンロードできるようにできないか？」→ 追加質問により**インターネット上の m3u8 URL**が対象と確定 |
| 要求の明確さ | 当初は曖昧（ローカルファイルか URL か不明）→ 質問と実測により明確化 |
| 要求の種別 | Enhancement（既存機能の補強）+ Bug Fix（子プロセスの停止漏れ） |
| スコープ | Multiple Components（Go バックエンド: 引数組み立て・ファイル名決定・プロセス停止 / フロントエンド: 警告とエラー表示） |
| 複雑さ | Moderate（純粋関数の追加は単純だが、プロセス停止方法の変更は OS 依存かつ既存の停止経路 3 つに影響する） |

**背景:** m3u8（HLS プレイリスト）の URL を登録して動画をダウンロードできるようにする。

実現可能性の評価は [m3u8-feasibility.md](m3u8-feasibility.md) を参照。評価の結果、**素の VOD m3u8 URL は
アプリを変更しなくても既にダウンロードできる**ことが実測で確認された（AES-128 暗号化 HLS、および映像・音声が
別レンディションの master playlist も成功）。したがって本要件は**新しいダウンロード経路を作るものではなく、
実用に耐えるための補強**である。

### 受け入れ方法

- m3u8 の URL は**既存の通常の登録経路（URL 入力欄・ドラッグ&ドロップ）でそのまま扱う**。
  m3u8 専用の入力欄・専用のダウンロード経路を作ってはならない
- **同時ダウンロード数 0（登録のみモード）の扱いも既存ルールのまま**とする。m3u8 のための例外を作らない
  （理由は下記「期限切れ URL」を参照）

### 保存ファイル名

**問題:** HLS の m3u8 にはタイトルのメタデータがない。そのため動画情報取得が返すタイトルは
**m3u8 のファイル名そのもの**（`master` / `index` / `playlist` / `chunklist` など）になり、保存名が
`master.mp4` に集中する。2 本目以降は連番付与により `master (1).mp4` となり、**中身を判別できない**。

- **m3u8 URL については、URL から取れる情報だけで区別しやすい保存名を自動生成する**
  - 構成要素: ホスト名 + m3u8 の 1 つ上のパス要素 + 登録日時
  - 例: `https://vod.example.com/hls/ab12cd/master.m3u8` → `vod.example.com_ab12cd_20260921-0915.mp4`
  - パス要素が無意味な場合（`master` などプレイリスト名相当の場合）は省略する
- 名前の組み立ては URL だけから決まる**純粋関数**とする（ユーザー入力欄を設けない）
- 理由: 保存名の入力欄を設ける案は、**ドラッグ&ドロップ経路では入力する機会がない**ため採用しない
  （ドロップは「追加」ボタンと同じ経路をそのまま辿り UI をブロックしないことが既存要件）
- 既存の同名ファイル保護（連番付与）は従来どおり適用する

### Referer（元ページの URL）

**問題:** m3u8 を配信するサーバは Referer を要求することがあり、その場合は素の m3u8 URL だけでは
`403 Forbidden` になる。実測で、Referer を渡すだけで 403 が解消することを確認した。

- **パスが `.m3u8` で終わる URL に限り**、その URL のオリジン（`https://host/`）を Referer として送る
- **適用を m3u8 URL に限定することは要件である。** 既存の 1000 以上の対応サイトは現在 Referer なしで
  動作しており、全 URL に Referer を送り始めるとそれらの経路の挙動を変えてしまう（デグレ）
- 視聴ページが別ドメインにあるサイトではこの方法は効かない。その場合の「元ページ URL をユーザーが
  指定して再試行する」機能は**今回の対象外**とし、必要性が確認されてから追加する

### 期限切れ URL

**問題:** m3u8 の URL は有効期限トークン付きのことが多く、失効すると 403 になる。**技術的な対策は存在せず**、
ユーザーが元ページから URL を取り直すしかない。本アプリは既定が同時ダウンロード数 0（登録のみモード）で
URL をキューに寝かせる運用が既定のため、**寝かせている間に失効する**。

- **登録時の警告**: m3u8 の URL を登録したとき、同時ダウンロード数が 0 であれば
  「m3u8 の URL は期限切れになることがあるため、すぐダウンロードを開始することを推奨」と伝える
- **失敗時の説明**: 403 で失敗したとき「URL が失効した可能性があります。元ページから取り直してください」と表示する
- **m3u8 URL を同時ダウンロード数 0 でも自動開始する例外は作らない。** 「0 のための特別分岐を追加しない」
  という既存の設計判断（[design.md](../application-design/design.md)「maxActive == 0」）を壊すため
- 失効して取り直した URL はトークンが変わるため、既存の重複登録防止（完全一致）の対象にならない。
  これは受け入れる（別アイテムとして登録される）

### 停止操作が子プロセスに及ぶこと（既存不具合の修正）

**これは m3u8 固有の要件ではなく、既存の不具合の修正である。** m3u8 のライブ配信を扱うと顕著に露出するため
本要件に含める。

**問題:** yt-dlp は処理内容によって **ffmpeg を子プロセスとして起動する**（ライブ HLS のダウンロード、
映像・音声の結合、MPEG-TS の修正など）。一方アプリの停止処理は yt-dlp のプロセスのみを対象としており、
**yt-dlp を停止しても ffmpeg が孤児として生き残り処理を続ける**ことが実測で確認された。

- **キャンセルは、yt-dlp が起動した子プロセスまで確実に停止させること。** 現状は yt-dlp だけが終了し、
  ffmpeg が裏でダウンロードを続ける（作業ディレクトリを削除しても書き込みが続く）
- **一時停止は、子プロセスまで確実に中断させること。** 現状は yt-dlp だけが止まり ffmpeg は動き続けるため、
  一時停止したはずのダウンロードが実際には進行している
- **yt-dlp の更新時のプロセス排出判定は、子プロセスの終了も待つこと。** 現状は yt-dlp の生存のみを見るため、
  ffmpeg が実行ファイルを掴んだままでも「排出完了」と判定する（Windows では置き換えが共有違反で失敗しうる）
- **停止対象は、そのダウンロードのために起動したプロセスに限定すること。** 無関係なプロセスを停止して
  はならない
- ライブ配信の「停止してそこまでを保存」は**対象外**（下記）

### セキュリティ要件

Security Baseline 拡張を有効にしたため（Q5 = Yes）、本要件に該当するルールを明示する。

- **Referer の値を yt-dlp のオプションに化けさせないこと**（SECURITY-05: 入力検証 / 既存の
  「引数インジェクション対策」と同じ攻撃面）。Referer は URL から導出するため、導出結果が
  `-` 始まりの文字列になる経路を塞ぐ。値は既存の URL 検証と同じ水準で検証し、
  http / https スキームかつホストを持つものだけを渡す
- **トークンを含む URL をログに平文で残さないこと**（SECURITY-03: ログに機微情報を出力しない）。
  現状 `moviedl.log`（ユーザー設定フォルダ内・0644・平文）には実行コマンド全体と yt-dlp の出力行が
  そのまま追記されており、**有効期限トークン付きの URL がクエリ文字列ごと記録される**。
  m3u8 の URL はトークンが実質的な認可情報であるため、ログに書く URL はクエリ部分をマスクする
- **停止対象を限定すること**（SECURITY-06: 最小権限の精神）。子プロセスまで停止範囲を広げる変更にあたり、
  そのダウンロードのために起動したプロセスのみを対象とし、無関係なプロセスに波及させない
- **エラー表示に内部情報を出さないこと**（SECURITY-09 / SECURITY-15）。403 の説明文などを追加する際、
  内部パスやコマンドラインをユーザー向けメッセージに含めない
- **失敗時に既存の状態を壊さないこと**（SECURITY-15: フェイルセーフ）。停止方法の変更が失敗した場合でも
  作業ディレクトリの後始末とリストの状態遷移が従来どおり成立すること

### 対象外

| 項目 | 理由 |
|---|---|
| ライブ配信の録画（停止してそこまでを保存） | 中断時の出力が 0 バイトで再生不能になることを実測で確認。子プロセスへの正常終了要求の設計が別途必要で作業量が大きい |
| ローカルに保存した .m3u8 ファイルの読み込み | ユーザー判断により対象外（対象はインターネット上の URL） |
| DRM 保護されたストリーム（Widevine / FairPlay / PlayReady） | 技術的に復号できない |
| 期限切れ URL の自動復活 | 技術的に不可能 |
| 元ページ URL のユーザー指定 | 必要性が確認されてから追加する |

## 非機能要件

### 配布形態

- インストール不要、1 ファイルで動作する
- macOS (Apple Silicon / Intel) および Windows 64bit に対応

### ファイル管理

- ダウンロード完了後のファイルは保存先フォルダに置かれる
- 保存先に同名ファイルが既に存在する場合は `タイトル (1).mp4` のように連番を付ける
- ダウンロード中に生成される中間ファイルは、完了後に確実に削除される
- 中間ファイルが残存した場合にユーザーが気づいて手動削除できること

### 自動リリース

- バージョンタグの push で macOS・Windows 向けバイナリが自動ビルドされ公開される
